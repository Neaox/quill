# ADR-064: Math

**Status:** Accepted
**Date:** 2026-11-12
**Related:** ADR-002 (Markdown is canonical), ADR-011 (security baseline), ADR-017 (testing and coverage), ADR-023 (public publishing and server rendering), ADR-031 (render caching), ADR-033 (compatibility), ADR-036 (diagrams and reading blocks), ADR-039 (Markdown extensions), ADR-060 (component blocks); `quill-plan.md` sections 21, 24 and 31

## Context

Documentation for engineering, science and finance carries formulas: an API's complexity, a pricing rule, a statistical definition. A Quill document written in Markdown had no way to say one. A `$` was a dollar, `$$` was two dollars, and a fenced block tagged `math` was a code block holding TeX it never drew. The same document rendered by GitHub, Pandoc or a static-site generator showed the formula; in Quill a reader saw the source.

The platform already has the pieces the feature needs: one Markdown processor and one renderer for every reading surface (ADR-002, ADR-023), a sanitiser that runs last over everything a page contains (ADR-011), a content-addressed render cache whose key includes what the renderer was made from (ADR-031), and an editor schema that round-trips every node it models (ADR-003). Math must join those paths rather than start a second one.

Two constraints decide most of the shape. TeX is not Markdown: `a*b*c` is a product, not emphasis, `\{` is a brace, and a `|` in a matrix is not a table delimiter. And a formula is authored content, so nothing in it may run script, load a resource, link anywhere, or carry an inline style the content security policy refuses.

## Decision

### What a document reads

**Inline math** is a pair of dollars in a sentence:

```markdown
The area is $\pi r^2$ for a circle.
```

**Display math** is a block between two `$$` lines, or one line holding `$$ formula $$`:

```markdown
$$
\int_0^\infty e^{-x^2}\,dx = \frac{\sqrt{\pi}}{2}
$$

$$ E = mc^2 $$
```

GitHub's fenced spelling, ```` ```math ````, draws the same block. It stays a `code` node in the tree with `lang: "math"`, so an editor that does not know math still reads the fence, and the renderer treats the fence tag as display math.

The syntax is a **micromark construct**, not a pass over the parsed tree (`packages/markdown/src/math/syntax.ts`). By the time a tree pass saw the text, CommonMark would already have interpreted `a*b*c` as emphasis and `` `...` `` as code. The tokenizer instead collects the formula's characters as a literal, exactly as a fenced code block collects its own. A construct may run over a line ending, as a code span may.

### Where a dollar is a formula, and where it is a dollar

A dollar is the most ordinary character in documentation: prices, shell prompts, variables. GitHub and Pandoc agree on the rules that keep those prose, and Quill uses them (`math/rules.ts`, written once and used by both the tokenizer and the writer):

- A dollar **opens** inline math when it is not preceded by another dollar and the character after it is neither space nor a dollar.
- A dollar **closes** inline math when the character before it is not space and the character after it is neither a digit nor a dollar.
- A backslash takes the character after it. `\$` is a dollar in prose, and a dollar sign inside a formula.
- Dollars inside code, a code fence or a raw HTML block are not math.
- A `$$` fence that is never closed is prose, not a block that swallows the rest of the document. The one-line form cannot interrupt a paragraph, and an empty `$$$$` is not math.

So `from $501 to $2,500` is prose, `$x$5` is prose, and `$a $b$` reads the second pair as the formula.

The tree holds the author's TeX and nothing derived from it: `inlineMath` in a sentence and `math` as a block, both literal nodes whose `value` is the source (`math/mdast.ts`). The names are `mdast-util-math`'s, so a tree from that extension is a tree for this one. A block written on one line records that spelling in `data.sourceForm.line`; it is used again while the formula still says the same thing, and the fenced form is written once it does not (`pipeline/source-form.ts`).

### Drawing it

TeX is drawn by **Temml 0.14.0** to MathML (`math/tree.ts`). Temml is pure JavaScript, runs in Node and in the browser, and emits the browser's own math markup: selectable, searchable, announced as maths by a screen reader, sized and coloured by the surrounding text, with no script, no web font and no second rendering path. KaTeX and MathJax were considered below.

Temml is configured as an untrusted renderer:

```ts
{ throwOnError: true, trust: false, strict: false, annotate: false, maxSize: [10, 120], maxExpand: 500 }
```

`trust: false` refuses `\href`, `\url`, `\includegraphics`, `\style`, `\class`, `\id` and the `\html*` commands; `annotate: false` keeps the semantic annotation out; the size and expansion limits stop a formula built to run away. A formula longer than `MAX_TEX_LENGTH` (20,000 characters) is refused before it reaches the engine.

The output is read off **Temml's own tree**, not parsed back out of its HTML. One neutral tree of `{tag, attributes, children}` is produced and then drawn two ways: to hast for the server renderer (`math/render.ts`), and to DOM nodes for the editor's preview (`math/dom.ts`, exported as `@quill/markdown/math`). Cleaning is written once.

A formula is drawn as:

```html
<span class="math" data-math="inline"><math>…</math></span>
<div class="math" data-math="display"><math display="block">…</math></div>
```

A formula Temml cannot read does not fail the document. The renderer shows the TeX the author wrote beside one line saying what is wrong: `<code title="Invalid math: …">` with an `sr-only` reason inline, and a `<pre>` with a visible reason in a block. The rest of the page reads, and the author can see what to fix.

### What the formula may contain

The grant (`math/grant.ts`) names every MathML element and attribute a formula may carry. Elements are `math`, `mi`, `mn`, `mo`, `ms`, `mtext`, `mspace`, `mrow`, `mfrac`, `msqrt`, `mroot`, `mstyle`, `mpadded`, `mphantom`, `menclose`, `msub`, `msup`, `msubsup`, `munder`, `mover`, `munderover`, `mmultiscripts`, `mprescripts`, `none`, `mtable`, `mtr` and `mtd`. `maction`, `semantics`, `annotation`, `annotation-xml` and `foreignObject` are absent.

Attributes are MathML presentation attributes with a value shape each: booleans, lengths, named spaces, alignments, small column and row spans, and the display flag. `href`, `src`, `id`, `style`, the `xmlns` declarations and every event handler are absent. Classes are kept only in the one shape Temml writes (`^[a-z][a-z\d-]*$`).

Temml writes a little layout as an inline `style`, which a page under `style-src 'self'` cannot carry. No style is kept. The few declarations that matter — table-cell padding, a tagged equation's widths, an `\hline` rule and one alignment — are translated to classes (`STYLE_CLASSES`); anything else, such as a colour or a size chosen with `\rule`, is dropped and the browser's own MathML layout applies.

Those classes and the two wrappers are styled in `packages/design-css/src/prose.css`, which the signed-in reader and the public site already share. A formula inherits the theme's colour, face and size, and a display block scrolls rather than widening the page.

The grant is checked twice. `math/tree.ts` keeps only what it names as Temml's tree is converted, and `render/sanitize-schema.ts` builds its allowlist from the same lists and runs last over the page, as ADR-011 requires. The attack corpus in `math/render.test.ts` holds links, pictures, styles, ids, classes, event handlers, raw `<math>` in an author's HTML, an unknown command, a deeply nested formula and a macro that expands for ever.

### Every surface, and the cache

Inline and block math are handled by the same mdast handlers as every other block (`render/handlers.ts`). `renderHtml` therefore draws them on the reading view, the public site, the presentation and the export, and the preview that renders through the format package uses the same call. There is no second renderer.

The editor schema gains two atoms, `mathInline` and `mathBlock`, holding `value` (the TeX) and the ordinary source-form attributes (`prosemirror/schema.ts`). Both directions are converted (`from-mdast.ts`, `to-mdast.ts`), so a formula survives a document being opened and saved, and a one-line block is written back in its one-line spelling until its formula is edited. The writing surface draws both atoms through `mathDom`, with the reader's engine and grant (`packages/editor/src/math/math-view.ts`), and an invalid formula shows its source and the reason rather than a blank.

The engine's version joins the Markdown registry's signature as `temml@0.14.0` (`extensions/registry.ts`). The signature is part of the render cache key (ADR-031), so upgrading Temml re-renders exactly the bodies that contain math, with no manual bump. `RENDER_VERSION` moves to 21 because this release changes what an existing document renders as; older cached versions stay readable (ADR-033).

Writing a tree back preserves math byte for byte. The writer escapes a dollar only where the rules would otherwise pair it into a formula, escapes a dollar standing against a formula, writes a digit after a closing dollar as a character reference, and separates two formulas that would touch with a zero-width space (`math/escape.ts`). Prices and prompts are left as they are.

### Tests

`math/rules.test.ts`, `math/syntax` through `math/math.test.ts`, `math/tree.test.ts`, `math/render.test.ts` and `math/escape.test.ts` cover the dollar rules, both forms, the writer's round trip and its generated cases, the grant, the attack corpus and the engine's limits. `prosemirror/converter.test.ts` covers the editor in both directions, the corpus gains `corpus/31-math.md`, and the converter and editor corpus tests run it with every other document. The render tests draw through the sanitised `renderHtml`, not the handlers alone.

## Alternatives considered

- **KaTeX.** Fast and familiar, but its HTML output needs its own CSS and web fonts, is not MathML, and gives a screen reader text positioned by spans rather than maths. It also has no tree API as small as Temml's, so the sanitiser would have to accept more of its markup.
- **MathJax.** The most complete TeX implementation, and the largest. Its rendering is asynchronous and needs fonts and CSS of its own, which is the wrong shape for a server-side render cached once and served to every reader.
- **A pass over the mdast tree after parsing.** It would have to undo CommonMark first: emphasis, escapes, tables and code spans would already have changed the source. The tokenizer is where the formula's bytes are still the author's.
- **Escaping every dollar on the way out.** It would keep meaning but rewrite every price and prompt in every document, turning a save into a diff. The rules-based writer escapes only what would otherwise change.
- **Rendering errors as nothing, or as a page-level error.** A single bad formula should not hide the document or leave a blank where a reader expects an answer. Showing the TeX and the reason is the degradation the rest of the pipeline uses (ADR-033).
- **Allowing Temml's inline styles through the sanitiser.** It would break the content security policy and make the sanitiser depend on one engine's spelling of CSS. Classes, or the browser's default layout, keep the policy and the engine independent.

## Consequences

- A document written for GitHub, Pandoc or a static-site generator shows its formulas in Quill, and still reads as Markdown where Quill is not rendering it.
- `@quill/markdown` gains six direct dependencies: `temml`, and the micromark and mdast packages the construct is written against. Temml is a runtime dependency of every surface that renders, including the server and the editor's preview chunk.
- Math is one more thing a cached body was made from; the engine's version is in the signature from the start, so a Temml upgrade is a re-render, not a version bump.
- Formulas are MathML. A browser without MathML support sees the fallback the document already carries — the TeX for an invalid formula, and the text content of the MathML for a valid one — and the reading stylesheet can enhance the wrapper without a second renderer.
- The grant is a closed list and will need extending deliberately when a new Temml command writes an element or attribute the list does not name. That is the intended cost: every addition is reviewed against the same attack corpus.
