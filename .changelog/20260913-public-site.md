Added: A collection can be published to the web. `POST /api/collections/:id/public` gives it an address and a viewer grant to the public principal; `DELETE` takes it down and keeps the address, so putting it back up answers where it always did. The site is server-rendered HTML with no application behind it — a home, a page per document at `/s/<site>/<collection>/<title>`, its own search, a sitemap of current paths only, and `robots.txt` — styled by the organisation's own generated theme over the same layout grid and reading typography the app uses, with light and dark following the reader's own preference (`docs/architecture/public-site.md`). A crawler gets canonical links, a description from the first paragraph, Open Graph tags, `Article` structured data and `lastmod` from the head revision; a reader gets an `ETag`, a `304`, and one stylesheet that is immutable because its address is its own hash. No public route reads a session, so the page is the same for a member as for a stranger. A draft is nowhere on it, and one document can be taken off the web with a deny to the public principal without hiding it from the people who write it. Renaming or moving a published page records the address it had and answers it with a `301`, so an old link keeps working. The server half only: the publish switch and the access screen come with the web work.
Fixed: A picture in a document is served to a reader with no account exactly when the document itself is public. `GET /api/attachments/:id` now takes an optional session and lets the permission resolver decide, so publishing a collection publishes its pictures as well as its text, and taking one document off the public web takes its pictures with it.
