Changed: An OIDC provider's client secret and the SMTP password are now resolved from the secrets store (`setSecret`/`getSecret`, envelope-encrypted under the instance master key, ADR-034) at the moment of use — the token exchange, an outbox mail send — rather than held anywhere for the life of the process. `OIDC_<ID>_CLIENT_SECRET` and `SMTP_PASS` still work as a fallback for one release, read fresh from the environment at that same moment: boot warns, naming the secret to set, whenever a provider or the mailer is only working because of the environment variable, and refuses to start when a secret names no readable value anywhere — including a row whose master key this instance no longer holds.
Security: Boot validation now fails closed when a stored secret's `keyId` is not one the current master key can unwrap, rather than reporting it configured and letting the failure surface later at a sign-in or a mail send.
Security: `OIDC_DEV_LOOPBACK`, the escape hatch letting the API server reach an OIDC provider on loopback for `e2e/sso.spec.ts`, is refused once `APP_URL` names anything but loopback *or* under `NODE_ENV=production`, and diverts only a provider whose own issuer is plain http — a real provider (Entra, Google, an on-prem Okta) is always `https:` and is never diverted, even on a developer machine that also has one configured.
Added: `pnpm --filter @quill/server secrets:set <name>`, beside `secrets:rotate`, lets an administrator or a deployment script enter a secret's value from stdin — never from a command-line argument (refused outright, along with a terminal stdin) — so it never sits in shell history or a process listing.
Added: `e2e/sso.spec.ts` drives single sign-on through a real browser against the in-process fake OpenID Connect provider, now runnable as its own process (`scripts/fake-oidc-server-cli.ts`): the sign-in page's "Continue with" button, a fresh sign-in, a returning person matched by subject rather than by the email they now use, and an unverified local account refused with the same error state as every other SSO failure.
