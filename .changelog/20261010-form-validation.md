Fixed: Sign-in, sign-up, magic-link and password-reset forms check what was typed before sending it. A missing or malformed email address, an empty password or name, and a password shorter than the server's twelve characters are each explained next to their field, in plain words, with focus moved to the first one to fix and the message cleared when it is edited. Previously the server's validator wording (`body/email must match format "email"`) was shown above the button.
Fixed: Sign-up and password reset asked for eight characters while the server requires twelve, so a password of eight to eleven characters passed the form and then failed. Setting a too-short new password after following a reset link also did nothing at all; it now says why.
Fixed: A request that never reaches the server is reported as "Could not reach the server. Check your connection and try again." instead of "Failed to fetch".
Changed: A request that fails the server's schema answers `400 validation_error` with a message naming the fields at fault (`The request was not valid: email.`). The validator's own findings are unchanged in `details`.
