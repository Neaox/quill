Added: `GET /api/workspaces` lists the workspaces a reader can actually reach, grouped by the unit they hang off, so the workspace picker asks the server rather than guessing. Visibility is decided by the same resolver a direct read uses, so the list can never offer a workspace that opening it would refuse.
Added: Collections can be created, renamed, listed and deleted through the API (`/api/workspaces/:id/collections` and `/api/collections/:id`). Renaming leaves the slug alone, so nothing that points at a collection has to move, and a collection that still holds documents refuses to be deleted rather than leaving its documents outside every collection.
