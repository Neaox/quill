Added: Instance administrators now configure the organisation through the product rather than through a file: `/admin/settings` carries the organisation's name and logo reference, the links on its public site (added, reordered, removed, with addresses validated against the same whitelist the public site is protected by), and the policies for share links, public publishing and how strictly a theme is judged. The organisation's name is what the top bar of every signed-in page now says, in place of the product's own.
Added: A theme editor with a live preview: accent, neutral tone, reading face, corner radius, density and per-collection colours, previewed on a real document in light and dark at once, with the palettes generated in the browser so every change shows before it is saved. The theme doctor's verdict sits beside the form — pass, adjusted or warn, with the reason — and an AA contrast failure is put in front of the instance switch that makes enforcement advisory, without ever refusing the save. Editing a built-in theme forks it, so the built-in stays as it shipped and can be reset to. Saving stores the theme and does not yet apply it across the product, which the screen says plainly: serving a tenant's resolved tokens with the page is ADR-028's delivery route and is not built.
Added: Layout is now chosen where ADR-028 says it belongs: the organisation sets the default arrangement for navigation, comments, history, the header and dividers, with an optional lock, and each workspace chooses its own from its overflow menu. A locked workspace is shown the arrangement it has and who decided it, rather than an empty panel.
Added: Secrets can be stored, replaced and deleted from `/admin/settings/secrets` through write-only fields — no response carries a value, so nothing in the product can show one again — beside a read-only list of the configured sign-in providers and the environment variables that change them.
Added: Leaving a settings screen with unsaved changes now asks, instead of discarding them. Moving between the four sections, going elsewhere in the product, and closing the tab are all covered.
Added: A save that is refused because somebody else saved first now offers both honest answers by name: start again from their version, or keep this form and replace theirs. Their values are shown either way, and whichever is chosen, their revision stays in the history.
Fixed: A settings file written by a newer release, which this release refuses to read rather than overwrite, can now be repaired from the product: an instance administrator is offered the revision the server reported and can overwrite the file through the API instead of editing a repository by hand.
Security: A settings form now compares against the revision it was actually loaded at, so a concurrent change is refused rather than silently overwritten. The revision used to be read from the query cache, which refetches when a window regains focus — so an administrator who switched away and back while a colleague saved would have overwritten them with no refusal and nothing on screen.
Security: A secret's value no longer outlives the dialog it was typed into. It was held as a mutation variable in the query cache for five minutes after the request settled, readable from the devtools and captured by anything that serialises cache state; it is now dropped as soon as the request resolves, and when the dialog is closed without one being made.
