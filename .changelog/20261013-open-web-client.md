Added: The server has an open-web fetch client for link previews, with public-address checks on every redirect, a single time budget covering the body, and reads that stop at the end of the page head.
Added: The domain has link-preview types and URL normalisation, and the server can resolve a URL to a preview through known oEmbed providers, Open Graph, Twitter Card and page tags, storing re-encoded thumbnails and favicons decoded in an isolated process.
Added: Organisations can be given a link preview policy: previews off, text only without images, or full, with allow and block lists of hosts and path prefixes that are enforced on every redirect, oEmbed endpoint and image a preview fetches.
Security: The link preview fetcher resolves names without the shared file-I/O threadpool, bounds how many fetches run at once, refuses to carry credentials, parses only the page head with a tag cap, and matches oEmbed patterns without backtracking; the image decoder runs with no environment.
Added: Links now have stored previews: the server looks up what is known for a page of links in one query, queues a background fetch for anything missing, keeps the last good preview through a failed refresh, and applies the viewing organisation's policy every time a preview is shown.
Added: Link previews are fetched on a lane of their own that never delays publishing or mail, a link directive records how an author wants a link shown, and previews, pictures and a page for site owners at /bot are served without ever letting an anonymous visitor cause a fetch.
Fixed: Calls to a sign-in provider or the password-breach service now stop on time even if the host sends its answer a byte at a time, and the object store and mail server have time limits.
Changed: Link preview images are decoded by a small pool of reusable workers, about 25 times faster and using a quarter of the memory of starting one process per image.
Added: Links an author has chosen to show as a chip or card now appear that way when reading a document, on the public site and through a share link; a link whose preview is still being fetched stays a plain link and the page looks again a few times, and publishing a document starts fetching the previews of its links.
Added: Links in a document show a small card of the page they go to while you rest the pointer on them or focus them, which can be turned off in Preferences and never appears on a touch screen.
Added: A link can be shown as a plain link, an inline link with the page's title, or a card: pasting an address offers the choice, the toolbar on any link changes it and, for a card, its layout, picture, title and description; `/link card` and `/link inline` insert one, and a card is drawn in the editor from its preview.
Changed: How a link is shown is now stored as an ordinary Markdown link with a hidden comment beside it, so a document still has clickable links in GitHub and every other Markdown tool; documents written the earlier way still read and are only rewritten when an author changes that link.
