Added: An instance administrator can build the organisation from the interface. `/admin/organisation` shows the unit tree with the workspaces inside it and creates, renames and deletes both; the home page's set-up card carries the first two steps — a unit, then a workspace in it — instead of describing them, and takes itself away once a workspace exists. Deleting is refused while anything is inside, with what is inside said in words: a unit names its workspaces and child units, a workspace counts its documents before the button is offered at all. None of it is rendered for anyone who is not an instance administrator, and the route itself answers "not available" to them.
Added: Collections can be created, renamed and deleted from the navigation sidebar — a "+" beside the workspace's name, and an overflow menu on each collection — and from the workspace home's empty state, which is where a workspace with nothing in it starts. A collection that still holds documents is not deleted: the dialog says how many it holds and offers to move them first.
Added: A document can be deleted, from its header's overflow menu or its row in the tree. The dialog names it and says what becomes of anything nested under it — the children are lifted to the top level of their collection, never deleted with it — and afterwards the person is back at the workspace with the tree already redrawn. There is no Undo, because there is no route that restores a deleted document.
Added: The signed-in home has its Continue and Recently updated sections: work that has never been published, and the newest published changes across every workspace, fetched per workspace in parallel and capped at ten. Each is omitted when it is empty. The sections say what the workspace document list cannot answer — who holds a lock, and whether a draft is ahead of what is published — rather than showing less than their names promise.
Added: `e2e/organise.spec.ts`, the journey that answers M2's acceptance question through the interface alone: a unit, a workspace, two collections, a document and a child nested under it, writing and publishing, renaming both, moving the child, deleting it, and deleting the collection it left behind — asserting the tree after each step — plus the refusal to delete a collection that still holds documents, and the same controls at phone width.
Changed: The workspace shell is a layout route. The header, the icon rail and the navigation sidebar are rendered once and never unmount while moving between the workspace home and the documents in it, so the screen no longer flashes on every navigation in the sidebar; pages render inside it, and their loading, error and not-found states render there too instead of replacing the whole page. Routes are now files under `apps/web/src/routes`, compiled into a generated route tree, each carrying its own data loading, 404, error state and page title.
Changed: The document tree is built from the workspace tree route rather than the flat document list, so a child document appears nested under its parent and collections are shown in the server's order — the same order the workspace home lists them in.
Changed: The workspace switcher offers every workspace the person can see, from the workspace list route, instead of only the ones this browser session happened to open; it sits at the head of the sidebar, where the workspace's name was, so the header does not say the name twice.
Changed: A document's address is now readable: `/w/engineering/d/authentication-architecture-k7m3q9v2rt` (ADR-035). Only the ten-character key decides, so a rename cannot break a link; an old address — a bare key, a stale title, a UUID — still resolves and the route corrects the address bar to the current form.
Fixed: Creating or renaming a document updates the navigation tree as well as the document list, instead of leaving the tree showing what was there before.
Fixed: A dialog no longer grows past the bottom of the window: its body scrolls, so the buttons in its footer stay reachable however long the form inside it is.
Fixed: The icon rail's links navigate through the router instead of reloading the whole application.
