Added: Images can be uploaded from the editor, not only linked by address. The image dialog gained a file field beside the address one, a file dragged onto the document or pasted into it opens the same dialog with the file ready, and alternative text is required before anything is inserted, so a picture always arrives with a description. A file that is not a picture — a PDF — becomes a link rather than a broken image. The Insert button carries the upload's spinner, a file over the limit is refused before it is sent, and a refusal from the server is shown in the dialog rather than leaving a broken image in the document.
Added: A document's attachments are listed from an "Attachments" panel on the document's own menu, with each file's type, size and date, and a delete that explains itself when a published document still shows the file.
Added: Attachments are stored in a blob store addressed by content hash, behind `BLOB_STORE=filesystem|s3`. The filesystem backend writes one content-addressed file per object and is what a backup copies; the S3 backend speaks any S3-compatible service, MinIO included. `POST /api/documents/:id/attachments` uploads, `GET /api/attachments/:id` serves, and `DELETE /api/attachments/:id` takes one down.
Security: An upload's content type is read from the file's own bytes rather than believed from the request, and a mismatch is refused. The allowlist is PNG, JPEG, GIF, WebP, AVIF and PDF; SVG is refused with the reason, because an SVG is a document that can carry script. The size cap is counted as the bytes arrive, so an oversized upload is refused rather than received.
Security: Attachments are served with `X-Content-Type-Options: nosniff`, a `Content-Security-Policy` of `default-src 'none'; sandbox`, `Content-Disposition: inline` only for images, and a filename encoded per RFC 6266 so a name in any script survives the header without being able to break it. Reading one needs `view` on the document that owns it; uploading and deleting need `edit`, and uploads are limited to 60 a minute per person.
Security: An attachment's cached copy is revalidated rather than held for a year, and the conditional request is answered after permission is checked, so a reader whose access is withdrawn stops being able to see it straight away.
Added: An attachment cannot be deleted while a published document still shows it. The refusal names the documents the person can open and counts the ones they cannot, so the fix is clear without revealing a workspace they have no access to; the bytes themselves are never removed, because another attachment may be the same picture and the blob store is a system of record.
