Added: The public site's header carries a menu the organisation builds in Settings → Organisation: standalone links and dropdowns of links, pointing at a document or a collection by id — so a rename or a move is in the header on the next page without anybody editing the menu — or at any https:// address. A link to something that is not on the web, or no longer exists, is left out rather than linked to a 404.
Added: The menu builder adds a link by searching documents and collections across every workspace with a keyboard-first combobox, or by pasting an address; edits labels in place, showing each target's current title beside a custom one; reorders by dragging or with move buttons; nests links in dropdowns; shows a deleted or unpublished target as one to fix; and previews the header live.
Added: The public header's dropdowns open on click and from the keyboard with no script at all, close on Escape with focus returned, on a click elsewhere, and one at a time; on a narrow screen the whole menu folds behind a Menu button. The reader preview shows the same menu.
Added: `GET /api/settings/organisation/public-menu/targets` and `GET /api/settings/organisation/public-menu/collections` (instance administration), which the menu builder uses to describe a menu's targets and to find collections by name.
Changed: Breaking: the organisation settings document is now version 2, and `publicNavigation` (a list of labels and addresses) is replaced by `publicMenu`. A version 1 file is still read — every link becomes an address link with the same label, address and order — and is written as version 2 the next time it is saved, so no migration has to be run. A client of `GET`/`PUT /api/settings/organisation` reads and sends `publicMenu` instead.
Security: A menu address is an absolute http(s) URL with no userinfo, or a rooted path on this site; `javascript:`, `data:`, protocol-relative and `user@host` addresses are refused. An external link always carries `rel="noopener"` and, by default, `noreferrer`; an administrator may let one partner link send the site's origin (never the page — `Referrer-Policy` is unchanged), and the reader preview and share pages never do, now answering with `Referrer-Policy: no-referrer`.
