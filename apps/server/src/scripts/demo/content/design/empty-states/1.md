# Empty states

An empty state is the screen someone sees when there is nothing to show yet. It is often the first thing a new customer sees in Tidepool, so it has two jobs: say why it is empty, and offer the one action that fills it.

## Three kinds

| Kind | Cause | What to show |
| :--- | :---- | :----------- |
| First use | Nothing has been created | A heading, one sentence on the benefit and a primary action: "Import feedback". |
| No results | Filters or a search match nothing | Echo the query, and offer "Clear filters". No primary action. |
| Cleared | The person finished the work, such as an empty inbox | Short congratulation, no action needed. |

## Writing the copy

Use a heading of six words or fewer and a single sentence below it. Be specific: "No feedback yet. Import a CSV file or connect Zendesk to start collecting it." Do not apologise or joke about the emptiness.

## Building it

The `EmptyState` component renders a `section` with a heading, so it appears in the page outline. It takes no illustration: Tideline avoids decorative graphics that need alt text. If you add an icon, mark it `aria-hidden`. The action is a [button](doc:Buttons), and it receives focus only when the empty state replaces content the person was just working in, such as after clearing the last item.
