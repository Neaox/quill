# Buttons

A button does something on the current page: saves, opens a dialog, starts an import. If it takes you somewhere else, it is a link. Getting that split right matters for screen reader users, who list links and buttons separately.

## Variants

| Variant | Use it for | Background | Label contrast |
| :------ | :--------- | :--------- | -------------: |
| `primary` | The one main action on a screen | `--color-accent-600` | 6.7:1 |
| `secondary` | Other actions of equal weight | `--color-neutral-0` with a 1px `--color-neutral-400` border | 17.4:1 |
| `ghost` | Low-emphasis actions in toolbars and tables | transparent | 17.4:1 |

A screen has at most one `primary` button. Two competing primaries mean the page has not decided what it is for.

## Sizes

| Size | Height | Horizontal padding | Type |
| :--- | -----: | -----------------: | :--- |
| `sm` | 2rem (32px) | 0.75rem | `--font-size-sm` |
| `md` | 2.5rem (40px) | 1rem | `--font-size-md` |
| `lg` | 3rem (48px) | 1.5rem | `--font-size-md` |

`md` is the default. Use `sm` in dense tables only; it still clears the 24px minimum target in WCAG 2.5.8.

## Usage

:::code-group
```ts [React]
import { Button } from "@tideline/react"

export function SaveBar({ onSave }: { onSave: () => void }) {
  return (
    <div className="save-bar">
      <Button variant="secondary">Cancel</Button>
      <Button variant="primary" onClick={onSave}>
        Save theme
      </Button>
    </div>
  )
}
```
```css [CSS tokens]
.btn-primary {
  background: var(--color-accent-600);
  color: var(--color-neutral-0);
  border-radius: var(--radius-sm);
  min-height: 2.5rem;
  padding-inline: var(--space-4);
}
.btn-primary:focus-visible {
  outline: 2px solid var(--color-focus-ring);
  outline-offset: 2px;
}
```
:::

## Do and don't

| Do | Don't |
| :- | :---- |
| Start with a verb: "Publish roadmap", "Import feedback". | Use "OK", "Yes" or "Submit" as a label. |
| Put the primary action on the right in a dialog footer, after Cancel. | Put two primary buttons side by side. |
| Use `aria-disabled` and keep the button focusable when you need to explain why it is unavailable. | Rely on a greyed-out look alone to say "you can't do this". |
| Keep labels to three words or fewer. | Wrap a label onto a second line. |

:::callout[Disabled buttons]{type=warning}
The `disabled` attribute removes a button from the tab order and lets contrast drop to nothing. Prefer to leave it enabled and show an inline message on activation. If you must disable it, put the reason in nearby text, not in a tooltip.
:::

## Accessibility

Use a real `<button>`, never a `div` with a click handler. Visible focus is a 2px ring in `--color-focus-ring` with a 2px offset, which has more than 3:1 against both the button and the page (WCAG 2.4.7 and 1.4.11). Icon-only buttons need an `aria-label`. See the [Accessibility checklist](doc:Accessibility checklist) for the full list.
