# Data tables

Tables are the workhorse of Tidepool: the feedback inbox, the theme list and the audit log are all tables. Use one when people need to compare values across rows. If each item is mostly prose, or the list is something people read rather than scan, use a list of cards instead.

## Structure

Build tables with real table elements: `table`, `caption`, `thead`, `tbody`, `tfoot`, and `th` with a `scope` of `col` or `row`. Screen readers use them to announce "Customers, column 3 of 4". A grid of `div`s with `role="table"` is a last resort for virtualised lists of more than about 500 rows, and then it carries `aria-rowcount`.

```ts title="src/features/themes/ThemeTable.tsx"
import { Table } from "@tideline/react"

type Theme = { id: string; name: string; items: number; customers: number }

export function ThemeTable({ themes }: { themes: Theme[] }) {
  return (
    <Table caption="Themes by feedback volume" sortable>
      <Table.Head>
        <Table.Column id="name">Theme</Table.Column>
        <Table.Column id="items" align="end" numeric>
          Items
        </Table.Column>
        <Table.Column id="customers" align="end" numeric>
          Customers
        </Table.Column>
      </Table.Head>
      <Table.Body>
        {themes.map((theme) => (
          <Table.Row key={theme.id}>
            <Table.RowHeader>{theme.name}</Table.RowHeader>
            <Table.Cell>{theme.items}</Table.Cell>
            <Table.Cell>{theme.customers}</Table.Cell>
          </Table.Row>
        ))}
      </Table.Body>
    </Table>
  )
}
```

## Alignment and density

| Content | Alignment |
| :------ | :-------- |
| Text, names, status | Start |
| Numbers, currency, durations | End, with `tabular-nums` |
| Icons and checkboxes | Centre, in a 2.5rem column |

Rows are 2rem (32px) by default, 2.5rem (40px) in the comfortable setting and 3rem (48px) on touch devices. Cell padding is `--space-3` horizontally. Header text is `--font-size-xs`, weight 600, in `--color-neutral-700` on `--color-neutral-50`. Use the density you have measured, not the one you prefer; the [Spacing and layout](doc:Spacing and layout) page lists the tokens.

## Sorting, selection and overflow

- **Sorting** is a button inside the column header, so it is reachable by keyboard. The header sets `aria-sort` to `ascending`, `descending` or `none`. One column sorts at a time.
- **Selection** uses a checkbox in the first column. The header checkbox selects the current page and shows the mixed state when only some rows are chosen. Announce "3 of 25 selected" in a polite live region.
- **Overflow**: let the table scroll horizontally inside a container with `tabindex="0"` and an accessible name rather than hiding columns. Below 40rem, switch to a stacked layout where each row becomes a labelled list, but keep the DOM as a table.

## Do and don't

| Do | Don't |
| :- | :---- |
| Right-align numbers and give the column a unit in the header. | Centre numbers or mix units in a column. |
| Put a total or summary in the `tfoot`. | Add a bolded "Total" row to the body. |
| Give every table a caption, even if it is visually hidden. | Use a table to lay out a form. |
| Show "No themes match these filters" with a clear-filters action. | Leave an empty body with only the headers. |

For the empty case, see [Empty states](doc:Empty states).
