# Mobile on-call guide

Mobile on-call covers Skiff on iOS and Android: the apps, their releases and the store accounts. It does not cover the Tidepool API or the sync endpoints behind it; those belong to the platform team's rota. If you are not sure which side a problem is on, start here, then hand over.

## The rota

One primary and one secondary, rotating weekly. Handover is Monday at 10:00 UK time in `#skiff-releases`: the outgoing primary posts open issues, any paused rollouts and anything they are watching. Seven engineers are on the rota, so you carry the pager about one week in seven. Pay and time off in lieu are set out in [On-call compensation](doc:On-call compensation).

- **Primary** takes every page and decides what to do.
- **Secondary** is the second pair of eyes during an incident and covers the primary's lunch, commute and flights.
- **Release manager** is a separate role. On-call can pause a rollout; the release manager decides what happens next.

Hours: pages are answered within 15 minutes between 07:00 and 19:00 on working days. Outside those hours, only severity 1 and 2 pages go to a phone. Everything else waits in the queue and is first in the morning.

## Your first hour

1. Acknowledge the page in PagerDuty. This stops the escalation to the secondary.
2. Open `#skiff-releases` and say "looking" with the alert name, so nobody else starts the same investigation.
3. Check the last release time. Most mobile incidents are within three days of one.
4. Decide the severity using the platform team's definitions and set it on the incident.
5. If customers are affected, tell Tom Becker's support team before you tell anyone else. They hear from Harbourview Health and Northwind Retail first.

## Common questions

::::accordion{name=on-call-faq}
:::details[A store review rejected our build on a Friday afternoon]
Read the rejection message in full. Apple's reviewers usually respond to a reply within a day, and Google's policy emails usually name the exact policy. If it is a metadata problem, fix and resubmit; if it is a code problem, tell the release manager before you change anything on the release branch.
:::
:::details[I cannot reproduce a crash that Sentry shows]
Look at the architecture and operating system breakdown first. Crashes that happen on only one OS version or only on 32-bit devices are usually native. Ask support for a device model and an app version from the customer, and borrow the closest phone from the device cabinet on the third floor.
:::
:::details[The API is down and Skiff is showing sync errors]
That is the platform team's incident, not yours. Page platform on-call, confirm that Skiff is queueing writes locally (it should be), and tell support that no data is lost. The apps keep working offline.
:::
:::details[Can I swap a shift?]
Yes. Agree it with the other engineer, change the PagerDuty schedule yourself and post the swap in `#mobile-eng`. You do not need approval.
:::
::::
