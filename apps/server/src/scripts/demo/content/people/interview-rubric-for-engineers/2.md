# Interview rubric for engineers

Every engineering candidate at Acme is scored against the same five competencies, whatever the level. Interviewers score independently and submit written feedback within four hours of the session, before they read anyone else's. The level we are hiring for sets the bar, not the rubric (see [Engineering levels and bands](doc:Engineering levels and bands)).

## The loop

| Stage | Length | Who | Focus |
| :---- | -----: | :-- | :---- |
| Recruiter screen | 30 min | Recruiter | Motivation, location, compensation expectations |
| Technical screen | 60 min | Engineer at E4 or above | Coding in the candidate's own editor |
| Onsite: coding | 45 min | Engineer | A small feature with tests, no puzzles |
| Onsite: system design | 45 min | Engineer at E5 or above | Trade-offs on a Tidepool-shaped problem |
| Onsite: debugging | 45 min | Engineer | Reading unfamiliar code and a failing test |
| Onsite: working together | 45 min | Hiring manager | Past projects, disagreement, feedback |

E3 and E4 candidates skip the system design session and get a second coding conversation instead. The loop is run on one day, remotely, with at most one 45-minute break between sessions. Every E5 and above loop includes one interviewer from outside the hiring team.

## Scoring

Each interviewer gives every competency they observed a score from 1 to 4:

1. No evidence, or evidence against.
2. Partial: some signal, but below the bar for the level.
3. Meets the bar for the level.
4. Clearly exceeds it, with a specific example to quote.

| Competency | What we look for | Red flag |
| :--------- | :--------------- | :------- |
| Problem solving | Clarifies the problem, tests as they go, recovers from a wrong turn | Writes code before asking a single question |
| Code quality | Names, structure and tests another engineer could pick up tomorrow | Cannot explain why the code is shaped the way it is |
| Technical judgement | Chooses the simple option and says what it costs | Reaches for a new framework for every problem |
| Communication | Explains a decision to someone who was not in the room | Answers in jargon and loses the interviewer |
| Collaboration | Takes hints well, asks for feedback, credits others | Dismisses the interviewer's suggestions |

## The decision

The debrief happens within 24 hours of the last session and is run by the recruiter. We recommend a hire when the average across all scores is at least 3.0 and nobody scored a competency 1. A single 2 is a conversation, not a veto; two or more in the same competency is a no.

> [!NOTE]
> Do not discuss a candidate in chat before you have submitted your own feedback. It is the most common way a loop goes wrong.

## Calibration

Dana Okafor's team reviews score distributions every quarter. In Q3 2026 the average onsite score was 2.8 across 61 loops, and offers went to 17 of them. If your scores are consistently a point above or below the rest of the panel, your hiring manager will pair you with a more experienced interviewer for two loops.

Offers are sized with the hiring manager using the bands, and the number of open roles comes from the [Engineering hiring plan 2027](doc:Engineering hiring plan 2027).
