# Errors

Tidepool uses conventional HTTP status codes. `2xx` means success, `4xx` means the request needs to change, and `5xx` means something went wrong on our side. Every error body has the same shape, so you can handle them in one place.

## The error envelope

```json
{
  "error": {
    "type": "validation_error",
    "code": "missing_field",
    "message": "body is required.",
    "param": "body",
    "request_id": "req_01JA5C9T2H"
  }
}
```

- `type` groups errors: `invalid_request_error`, `authentication_error`, `permission_error`, `validation_error`, `rate_limit_error` and `api_error`.
- `code` is stable and meant for your code to branch on.
- `message` is for people and may change. Never parse it.
- `param` names the offending field when there is one.
- `request_id` identifies the request in our logs. Include it when you write to support.

## Status codes and error codes

:::table[Errors you can expect]{width=wide}
| Status | Code | Meaning | Retry? |
| -----: | :--- | :------ | :----- |
| 400 | `invalid_request` | Malformed JSON or an unknown parameter | No |
| 400 | `invalid_cursor` | The pagination cursor is malformed or older than 24 hours | Restart from page one |
| 401 | `invalid_token` | The token is missing, malformed or revoked | No |
| 401 | `token_expired` | The token passed its expiry date | No |
| 403 | `insufficient_scope` | The token lacks the scope this endpoint needs | No |
| 404 | `not_found` | No such object in this workspace | No |
| 409 | `idempotency_in_progress` | The first request with this key is still running | Yes, after a pause |
| 422 | `missing_field`, `invalid_value` | A field failed validation | No |
| 422 | `idempotency_key_reuse` | The key was already used with a different body | No |
| 429 | `rate_limited` | Too many requests | Yes, after `Retry-After` |
| 500 | `internal_error` | Unexpected failure | Yes, with backoff |
| 503 | `unavailable` | Temporarily overloaded or in maintenance | Yes, with backoff |
:::

## Questions

::::accordion{name=errors-faq}
:::details[Why is a validation failure 422 and not 400?]
`400` means we could not understand the request at all. `422` means we understood it and a value was unacceptable, for example a `source` that is not one of `support_ticket`, `interview`, `widget`, `csv_import` or `api`. The `param` field points at the value.
:::
:::details[Which errors should I retry?]
Retry `429`, `503` and `500` with exponential backoff, and only retry `POST` requests that carry an [Idempotency](doc:Idempotency) key. Honour `Retry-After` on a `429`, as described in [Rate limits](doc:Rate limits). Never retry other `4xx` responses: the same request will fail the same way.
:::
:::details[Does a failed request count against my rate limit?]
`429` responses do not count. Other `4xx` and `5xx` responses do, because Tidepool still did the work of rejecting them.
:::
::::
