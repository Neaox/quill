# Authentication

Every request to `https://api.tidepool.example/v2` must carry a bearer token in the `Authorization` header. Tokens belong to a workspace, not to a person, so an integration keeps working when someone leaves your team.

## Send the token

:::code-group
```bash [curl]
curl https://api.tidepool.example/v2/themes \
  -H "Authorization: Bearer $TIDEPOOL_TOKEN"
```
```ts [TypeScript]
const response = await fetch("https://api.tidepool.example/v2/themes", {
  headers: { Authorization: `Bearer ${process.env.TIDEPOOL_TOKEN}` },
})
if (!response.ok) throw new Error(`Tidepool returned ${response.status}`)
const { data } = await response.json()
```
```py [Python]
import os
import requests

response = requests.get(
    "https://api.tidepool.example/v2/themes",
    headers={"Authorization": f"Bearer {os.environ['TIDEPOOL_TOKEN']}"},
    timeout=10,
)
response.raise_for_status()
```
```go [Go]
req, _ := http.NewRequestWithContext(ctx, http.MethodGet, "https://api.tidepool.example/v2/themes", nil)
req.Header.Set("Authorization", "Bearer "+os.Getenv("TIDEPOOL_TOKEN"))
res, err := http.DefaultClient.Do(req)
```
:::

The official SDKs set the header for you when you pass `token`.

## Token types

Workspace admins create tokens under **Settings → API → Tokens**. The prefix tells you what a token can reach.

| Prefix | Environment | Notes |
| :----- | :---------- | :---- |
| `tp_live_` | Your workspace data | Counts against your plan's [rate limits](doc:Rate limits) |
| `tp_test_` | Sandbox | Isolated data, reset on the first of each month |

A token is shown once, when you create it. Tidepool stores only a hash, so a lost token cannot be recovered; create a new one and revoke the old.

## Scopes

A token carries one or more scopes and can do nothing else. Grant the smallest set that works.

| Scope | Allows |
| :---- | :----- |
| `feedback:read` | List and retrieve feedback |
| `feedback:write` | Create, update and delete feedback |
| `themes:read` | List and retrieve themes |
| `themes:write` | Create, rename and merge themes |
| `roadmap:read` | List and retrieve roadmap items |
| `webhooks:manage` | Create and delete webhook endpoints |

A call that needs a scope the token lacks fails with `403` and the code `insufficient_scope`.

## Expiry and rotation

Since release 2026.10 you can give a token an expiry date when you create it, up to 365 days ahead. Tokens created without one expire after 365 days, and existing tokens keep working until 12 October 2027. Tidepool emails the workspace admins 14 days before a token expires. After expiry, requests fail with `401` and the code `token_expired`.

Rotate without downtime by overlapping two tokens:

1. Create a second token with the same scopes.
2. Deploy it to every service that uses the old one.
3. Check **Last used** on the old token in **Settings → API → Tokens**. When it stops moving, revoke it.

:::callout[Check the response, not the clock]{type=tip}
Treat a `token_expired` response as a signal to alert a human, not to retry. Retrying an expired token only burns your rate limit.
:::

> [!WARNING]
> Never put a token in a browser, a mobile app or a public repository. Call the API from your server. If a token leaks, revoke it in **Settings → API → Tokens**; revocation takes effect within seconds.

> [!NOTE]
> A missing, malformed or revoked token returns `401` with the code `invalid_token`. See [Errors](doc:Errors) for the full envelope.
