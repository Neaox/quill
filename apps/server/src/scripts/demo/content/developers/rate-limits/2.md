# Rate limits

Tidepool limits how many requests a workspace can make, counted per token over a sliding 60-second window. The limit depends on your plan.

| Plan | Requests per minute | Batch requests per minute |
| :--- | ------------------: | ------------------------: |
| Starter | 60 | 10 |
| Team | 600 | 60 |
| Business | 1,200 | 120 |
| Enterprise | Custom | Custom |

A batch request is a call to `POST /v2/feedback/batch`, which accepts up to 100 items. It also counts against the general limit, once. Team limits doubled in 2026.10.

## Read the headers

Every response tells you where you stand:

- `RateLimit-Limit`: your requests per minute.
- `RateLimit-Remaining`: requests left in the current window.
- `RateLimit-Reset`: seconds until the window has room again.

## When you hit the limit

Tidepool returns `429 Too Many Requests` with the code `rate_limited` and a `Retry-After` header giving the seconds to wait. Wait at least that long, then retry. Slow down before you reach zero: if `RateLimit-Remaining` drops below 10% of the limit, spread your calls out.

If you retry on your own schedule, use exponential backoff with jitter: wait 1 second, then 2, 4 and 8, each plus a random 0 to 500 ms, and give up after five attempts.

Requests that return `429` are not counted, but a client that ignores `Retry-After` and keeps sending will be blocked for five minutes. See [Errors](doc:Errors) for the response shape.
