# Release notes 2026.9

Released 15 September 2026. This release adds a batch endpoint for loading feedback, a new webhook event, and a larger page size. It also announces the retirement of v1.

## New

- :accent[New] **Batch create.** `POST /v2/feedback/batch` accepts up to 100 items in one request and returns a per-item result, so one invalid item no longer fails the whole call. The response is `207 Multi-Status` when some items succeed and some fail. Batch calls have their own allowance; see [Rate limits](doc:Rate limits).
- :accent[New] **`theme.merged` webhook.** Sent when two themes are merged. `data.object` is the surviving theme and `data.merged_theme_id` is the one that was removed. Add it to an endpoint's `events`, or use `["*"]`. See [Webhooks](doc:Webhooks).
- :accent[New] **Filter by theme.** `GET /v2/feedback` accepts `theme_id`, and `theme_id=none` returns feedback not yet assigned to a theme.
- :accent[New] **Go SDK 2.5.0.** Adds an iterator for every list endpoint and context cancellation on retries.

## Improved

- :ok[Improved] **Page size.** The `limit` parameter on list endpoints now goes up to 100. It was 50. The default is still 25.
- :ok[Improved] **Faster feedback search.** `GET /v2/feedback?q=` is about 40% faster at the 95th percentile on workspaces with more than a million items.
- :ok[Improved] **Clearer validation errors.** `422` responses now set `error.param` to the full path of the field, such as `author.email`.

## Fixed

- :ok[Fixed] `PATCH /v2/feedback/{id}` no longer clears `tags` when the body omits them.
- :ok[Fixed] The `Retry-After` header on a `429` is now always an integer number of seconds.

## Deprecated

- :warn[Deprecated] **API v1.** v1 will become read-only on 1 January 2027 and will be switched off on 31 March 2027. Start with the [migration guide](doc:Migrating from v1 to v2). v1 responses now include a `Deprecation: true` header and a `Sunset` header with the final date.

## Upgrading

No change is required for existing v2 integrations. SDK users should update to TypeScript 2.7.0, Python 2.6.0 or Go 2.5.0 to get the batch methods, and read the [SDK overview](doc:SDKs and libraries) for install commands.

:::details[Why does a batch return 207 instead of 200?]
A `200` would hide partial failure. With `207 Multi-Status` the body's `results` array has one entry per item, in the order you sent them, each with its own `status` and either the created object or an `error`. Check every entry, not just the HTTP status. Send an `Idempotency-Key` with the batch so that retrying the whole request is safe.
:::
